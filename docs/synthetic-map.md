# Synthetic map

Run `npm install` and `npm run dev`, then follow **Synthetic map** from the project navigation. Supabase, Docker, workers, credentials and browser geolocation are unnecessary. No collection is implemented: changing the selected area, panning, zooming and reading results only query bundled fictional offers.

The renderer is Leaflet 1.9.4, using its standard geographic circle (radius in metres), marker, drag, keyboard navigation and zoom controls. [Leaflet API reference](https://leafletjs.com/reference.html). The map uses OpenStreetMap standard raster tiles at `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, with visible OpenStreetMap contributor attribution. No key is required. Tile requests require internet access and send the browser's normal referrer; default HTTP caching is retained. Do not prefetch or bulk-download tiles. Follow the [OSM tile usage policy](https://operations.osmfoundation.org/policies/tiles/) for your usage. The provider URL, maximum zoom and attribution are configured together in `src/SyntheticMap.tsx`; replace all three together if switching providers. Tile failure displays a message while coordinate controls and results remain usable. Existing landing-page fonts also use Google Fonts when online.

Shared JSON contracts are in `src/listings/contracts.ts`, copied from #2 and #5. `queryListings(AreaQuery): Promise<AreaResults>` in `src/listings/query.ts` validates runtime input and reads fixtures only. It rejects invalid input distinctly from successful empty results. UI coordinate drafts are strings converted explicitly at form submission; the query boundary rejects strings. Invalid drafts retain the last accepted area. Great-circle distances use metres and mean Earth radius 6,371,000 m, matching Leaflet's Earth-distance convention; longitude differences wrap through the periodic haversine. A 0.00000001 m tolerance handles floating-point equality at the inclusive boundary. This is a spherical geodesic approximation, rather than an ellipsoidal survey calculation.

Fixture recipe: `sample-sale-1` at (35,135), explicitly free and unknown availability, and `sample-rent-1` at the same point, monthly ¥35,000. `sample-unknown-1` at (35.001,135) has unknown sale money. `sample-unavailable-1` at (35.002,135) is explicitly unavailable; `sample-outside-1` at (36,135) is outside the default circle. All positions are synthetically verified. Additional boundary and antimeridian offers at (0,0) and (0,-179.99) support deterministic geographic checks. Their timestamps are fixed at 2026-10-15T00:00:00Z. The #5 synthetic source identity, Japanese sale title, source host and timestamps are retained. These records are not collected data or real offers. Source links use reserved `example.invalid`; tests control navigation and never request a real bank.

Every visible offer has its own list entry and stable identity. Coincident markers may overlap; the list keeps all offers reachable. Pin and list selections share one details view. Unavailable visibility is applied by the query before rendering both. Unknown availability remains visible. Missing results and query failures never mark offers withdrawn. Source text is rendered by React as text; navigation is HTTP(S), credential-free and restricted to each source's configured exact hostname. Coverage remains unknown and prominently synthetic.

Issue #8 covers verified fixtures. The contract's other location variants and municipality groups are reserved unchanged for later tickets; they are not fabricated here. No imports, geocoding, translations or live source support are supplied by this slice.

Validation uses `npm test`, `npm run test:e2e`, `npm run lint`, `npm run build`, and `npm run format:check`. Browser map tests are necessary for real Leaflet SVG layout, marker pointer hits, pan/zoom and pointer coordinate conversion; tile requests and source navigation are controlled. Additional UI drafts/money cases use simulated DOM tests. Geographic membership is observed through the public query response, without map internals.
