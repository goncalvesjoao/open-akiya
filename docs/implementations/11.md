# Inspect area-associated unknown-location listings

Ticket: https://github.com/goncalvesjoao/open-akiya/issues/11. Contracts: [#2](https://github.com/goncalvesjoao/open-akiya/issues/2), [#5](https://github.com/goncalvesjoao/open-akiya/issues/5). ## Behavior and decisions

The synthetic adapter has authored, fixed discovery query areas for unknown-location fixtures. These areas describe discovery relevance, never house coordinates. Broad discovery can also reveal a precise position during detail normalization; the precise position takes precedence when reading results.

Successful listing commits save their discovery query circle in a worker-private SQLite table in the same transaction. Unknown-location candidates are returned only when a saved circle intersects the selected area. Unrelated saved unknown offers are excluded. Existing precise and unverified point filtering takes precedence over this broad evidence. Discovery evidence does not enter the listing DTO. Existing databases gain the additive table; older offers without saved evidence remain excluded until an explicit import supplies evidence.

The renderer places unknown offers in a separate Unknown location list and uses the existing selection and details view, Japanese source text, successful-check time and validated source action. Entries explain that exact location and distance are unknown. No pins, house distances, coordinates, geocoding, translation or live sources were added. The adapter's default one-offer runtime recipe is preserved; desktop sample imports explicitly include the new fixtures.
