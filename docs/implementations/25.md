## Implementation and decisions

Manual refresh has worker-private durable intent, its original request cutoff, and durable aliases for repeated pending actions. The public request/job DTOs remain unchanged; the existing create input now accepts `manual_refresh`. A terminal action starts new intent while retries of an old key retain their original request.

The shared job's terminal transaction either satisfies the attached manual request with successful checks since its cutoff or links one bounded follow-up. That job uses the requested circle, existing refresh allocation, and saved completed discovery. Incomplete discovery cursors transfer only within the same query scope. A covering traversal can prove narrower discovery but cannot transfer its date checkpoint to the narrower query. Queue dispatch cache reuse cannot turn manual intent into a cached response.

Follow-ups stop truthfully at their budget. Explicit continuation carries the original cutoff and deferred refresh obligations, including rejected rechecks. Cancelled requests detach shared execution and cancel exclusively owned work. All progress and saved observations remain local; no additional worker, DTO, dependency, or live-source collection was introduced.

A manual response whose adapter check predates the cutoff is rejected and remains continuable. Resuming progress without any detail-check time no longer serializes an infinite placeholder as null and accidentally treats it as the Unix epoch.
