## Implementation and decisions

Creation atomically attaches identical or contained areas with compatible frozen source/filter/reference semantics. Independent request IDs and immutable areas survive job state updates. Partial overlaps queue. Request cancellation immediately detaches one intent; only its last active owner cooperatively cancels execution. Explicit job cancellation affects unfinished owners. Terminal requests never reopen, and cancellation does not erase committed results.

Queued work reconsiders successful checks obtained since submission, retaining exact adapter semantics and a strict 24-hour expiry. Reused details do not increment checked or request counts. Recovered queued requests can become cached historical references with original successful-check evidence. The unused queue record retains zero attempts and a CACHE_REUSED reason. Freshness cannot extend beyond the oldest required successful detail check. Shared complete response fixtures are in `src/shared/import-fixtures.ts`.

No approved deviations. General freshness reuse from before queue submission, configurable freshness and area-results coverage selection remain #20. Manual refresh, continuation, allocation and checkpoints remain sibling work. This ticket does not complete #6 or #3. An adapter ignoring cancellation must settle before execution can stop.
