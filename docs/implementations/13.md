## Implementation summary

The Electron utility-process API now accepts a persisted base import intent with separate request and job IDs. Exact selected areas, intents, identifier inputs and active-job query arguments are validated in the worker. Atomic idempotency mappings survive restart and reject conflicting input with typed errors. Different keys create independent requests/jobs; active-work attachment remains outside this ticket.

A SQLite transaction claims an installation-wide executor lease. Heartbeats, owner/expiry checks and fenced writes prevent another runtime from executing the same live job. Scope includes enabled source capabilities and versions, reference version and filters, and cannot change after acknowledgement. Startup does not reset another worker's live job. Graceful interruption retains committed candidate progress; saved listings remain available after restart.

The independent synthetic adapter implements discover, detail and normalization stages against one fixed offer at 35° N, 135° E. Discovery/detail attempts are counted before dispatch. Observation, approved projection, committed outcome counts and candidate progress are saved atomically. Stable saved listing IDs and successful-check timestamps survive repeats; unchanged content is counted separately. Results only read saved listings and never collect.

The preload exposes the six approved domain methods. Main checks the owning WebContents, main-frame identity and exact application URL before dispatch; utility-process dispatch validates arguments. Errors are sanitized and projected field construction excludes private observation data, operational fields and nested unexpected adapter fields. Renderer consumers use the approved request/job DTOs; English synthetic display names derive from stable source identities rather than generated listing IDs.

## Material decisions and tradeoffs

- Keep existing listing and observation tables and identities. Add versioned request/job/lease tables rather than destructively converting foundation records. Historical foundation jobs are retained privately but not resumed/exposed as invented intents. No pending-job migration is claimed.
- Use a renewable SQLite lease, with database owner/expiry checks before outbound dispatch and commits, rather than relying on Electron's main-process single-instance lock.
- Default synthetic mode imports one fixed offer. Geographic test fixtures inject the same adapter with additional fixed offers, preserving boundary/antimeridian and availability checks without broadening default import scope.
- Base saved-area coverage remains conservatively unknown and freshness is null. Job source coverage reports completed synthetic traversal; no cache, checkpoint or real-inventory completeness is inferred.
- Keep baseline job cancellation/restart behavior while migrating its contract, without claiming the full acceptance of sibling tickets #17/#18.
- Existing renderer import consumers are adapted only enough to consume the approved contracts; the integrated UI journey remains #7 work.
