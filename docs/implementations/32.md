## Implementation and decisions

The existing renderer/preload/main/utility-process/SQLite path remains the only
implementation. Integrate the missing verified unavailable offer into its authored
fixture collection, preserving candidate order for bounded continuation. The real
Electron journeys exercise all location categories, unavailable filters and summary
counts, including an outside-circle municipal office and list-only unknown offers.

Add a development-only source-failure transport behind the existing isolated test
profile gate. Attempts still pass through worker accounting, scheduling, error
classification and durable settlement. Saved-data reads remain real SQLite reads.
The failure journey imports first, relaunches with source failure, requests refresh,
changes its current circle, and checks retained listings, actual successful-check
times, current-area pins/list, and reconnect behavior. No renderer policies or
alternative worker are introduced.

A shared fixed-image tile responder serves successful tiles for integrated journeys
and rejects other HTTPS traffic. The selected-area journey verifies loaded tiles
and actual pan/zoom without active work or committed saved results. The existing
query-recovery journey retains its deliberate query/tile failures as supplementary
UI evidence, not runtime acceptance. Extend refresh acceptance to withdraw pending
follow-up intent through its real UI control. Document local usage and fixture
switches in [desktop runtime](../desktop-runtime.md#run-the-integrated-synthetic-workflow).

No approved deviations. No live-source or aggregate #3 completion claim. Runtime
source traffic is synthetic; live place search/tiles are controlled in acceptance.
Platform installer/signing validation remains outside this slice.
