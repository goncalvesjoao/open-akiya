## Implementation

The renderer follows server-returned active queue ordering and immutable job areas, exposes cancellation independently for every accepted request intent and each queued/running job, retains terminal history and counts, and refreshes current-area saved results at settlement. Running cancellation remains pending until the worker returns a terminal outcome. Stale polls cannot overwrite a newer action response. Minimal retained request IDs allow request cancellation after renderer reload; worker snapshots remain authoritative. Missing reconnect IDs are discarded individually on `NOT_FOUND`, while transient failures remain retryable. Fully settled IDs leave browser storage only after request terminal state, no pending follow-up, and terminal linked jobs; visible request history remains intact.

No approved deviations. Full interruption recovery, refresh and continuation controls remain sibling-ticket scope. Scheduling, attachment and ownership policies remain in the existing worker; no contract changes were required.

Shared full snapshots in `src/shared/cancellation-fixtures.ts` serve DOM and temporary-SQLite worker tests. The Electron test uses a four-second detail delay guarded by unpackaged test mode, a test-data path and hidden-window flags. It exercises real sandbox IPC, queue decisions, current-area map/list refresh and restart without live-bank requests.
