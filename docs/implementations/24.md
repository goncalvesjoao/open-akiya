## Implementation and decisions

Private SQLite checkpoints use the source, exact job query scope, adapter version and date field. The scope already freezes the area, source/query capabilities, filters and geographic reference version. Exact matching is conservative and never borrows another area's dates. The boundary is the newest reliable date from a completed traversal. Subsequent scans consume equality and the inclusive overlap before stopping strictly below it. Every received page and the cross-page order are checked before stopping; unsupported, missing, invalid or inverted date evidence disables optimization and promotion for that traversal.

Promotion shares the final successful job/request transaction. Incomplete, failed, cancelled and source-limited jobs cannot advance it. Candidate commits keep observation, listing, counts and progress atomic. The existing private `source_traversals` payload retains `dates`, `discoveryComplete` and `refreshLoaded` for continuation integration. Its date evidence contains `reliable`, `newestAt`, `lastAt` and the previously completed `stopBefore` boundary. These are worker records, not client DTO additions.

After discovery finishes, stale saved offers remain independently eligible for counted detail checks in oldest-check order, even when publication-date discovery stopped before them. This uses the contract's 24-hour default and existing detail budget. Discovery coverage can be complete while an older detail refresh fails; job outcome, error and caveat disclose unfinished required work, and successful-check time remains unset. Area-results coverage remains conservatively unknown. No fresh cache or real-world inventory completeness is inferred.

The existing multi-source test fixtures lacked controlled waits after request pacing was introduced. They now use the shared deterministic clock instead of real two-second waits. Their timestamps reflect actual checks, and an all-rejected refresh correctly expects failure when the current job saved no useful work. Other availability/history assertions remain intact. The parent observed nine baseline timeouts before these fixture corrections.

No approved deviations.

## Limitations and completion gate

Cross-job checkpoint acceptance is incomplete pending [#23](https://github.com/goncalvesjoao/open-akiya/issues/23), which owns explicit continuation and cursor invalidation. Its integration must preserve date evidence and exact scope through continuation, discard abandoned traversal evidence on invalid cursors, and verify promotion only after all inherited required work commits. This implementation does not claim that acceptance criterion or completion of #6/#3. Keep the PR draft until that verification passes.

Configurable freshness and fair refresh reservation remain #22. This change only preserves older-offer refresh eligibility needed by discovery stopping. No live source transport or live inventory is enabled. Source-declared ordering of unseen pages remains an adapter evidence requirement.
