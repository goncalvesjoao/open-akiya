## Implementation

The renderer persists reconnectable request/job identifiers and validated selected area, then restores authoritative scope, stages, counters and pending follow-ups through request inspection, linked jobs and the active queue. Temporary inspection failures retain saved results and offer Reconnect imports; independent inspection failures do not prevent healthy work from being observed. Terminal history is inspected without resubmission.

Storage contains identifiers and selection, never progress snapshots. Terminal identities remain available for relaunch history. Invalid stored selection is discarded; unavailable browser storage degrades to active-queue discovery. No approved deviations.

No worker scheduling policy changes were required. Issue #18 remains independently open; existing runtime recovery and cancellation capabilities are exercised by the current worker tests. The #25 pending-follow-up integration uses the existing real SQLite API tests and shared full response fixtures.
